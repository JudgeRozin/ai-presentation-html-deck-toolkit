01 · The problem

Corrections fail in language, not in design

What usually happens

“change the blue one, bottom right”

  • The agent guesses a DOM path — and often guesses wrong.
  • Every wrong guess costs a full render + QA round.
  • No artifact proves which element was meant.
What a deck with a picker gives you

  • Slide number — scopes the search to one section.

02 · Feature 1

Element Picker — press P

Four steps, zero setup
  1. Press P (or click 🎯 Pick element). Cursor turns crosshair.
  2. Hover: cyan outline + tooltip showing slide, DOM path and text.
  3. Click: the reference is copied to clipboard, gold flash + toast.
  4. Press Esc to exit. P toggles.
  • Picker chrome is excluded via UI_SEL — you never pick your own tool.
  • Click handler runs in capture phase, so deck navigation never fires on a pick.

03 · Feature 2

Multi-picker — press M

Batch references in one paste
  1. Press M (or click 🔲 Multi-pick). A panel appears with a counter.
  2. Click as many elements as you want — each gets a gold ring.
  3. Or hit the ⊕ badge in a slide corner to select that whole section.
  4. Copy refs copies the batch; Clear resets; Esc exits.
  • Refs are sorted in DOM order (compareDocumentPosition), not click order.
  • Section refs point at #slide-N, so "this whole slide" is one instruction.

04 · Feature 3

PDF export — 1 slide = 1 page

No generator, just print CSS
  • ⤓ PDF button in the nav calls window.print().
  • Export a section… dropdown prints a subset — page count still matches.
  • @page{size:1280px 720px} — exact 16:9, no A4 white bars.
  • print-color-adjust:exact — dark backgrounds survive without ticking "Background graphics".
  • Slides are pinned to 720px in print; flex children can't collapse.
Proof, not vibes
@media print{
  @page{size:1280px 720px;margin:0}
  .slide{width:1280px!important;height:720px!important;
    page-break-after:always;break-after:page}
}
